# 実装計画

対象: [bonsai/github-start](https://github.com/bonsai/github-start)

## 方針

まず既存の「4コマ・横一列・右へ進む」体験を磨く。八コマ原稿は価値ある次段階の案として保持し、画面全体を一度に変更しない。小学生と保護者が迷わず進めること、安全に操作できることを優先する。

## フェーズ

### Phase 1 — 安全な入口

- [ ] #1 登録CTAとREADMEの年齢条件を一致させる
- [ ] #2 Museビューにも年齢条件・保護者確認・コネクタ権限確認を追加する

完了条件:
- 13歳未満の子ども本人にアカウント作成を促す表現がない
- 保護者自身のアカウントで保護者が操作する方法が明確
- 接続許可の範囲を確認してから承認することが明確

### Phase 2 — 迷わない操作

- [ ] #5 次へ進めるパネルに視覚的ヒントを表示する
- [ ] #4 ビュー切替をタブまたは通常ボタンのどちらかに統一する

完了条件:
- 次へ進める場所と最終パネルの違いが視覚的に分かる
- キーボードだけでビュー切替とパネル移動ができる
- ARIAの状態と実際の操作が一致する

### Phase 3 — 保守と公開

- [ ] #6 Pagesの公開状態・URL・設定手順をREADMEに記載する
- [ ] #3 CSSの重複を整理する

完了条件:
- READMEから公開ページを開ける
- CSS整理後も両ビューのレイアウトが維持される
- ページタイトルとREADMEの名称が一致する

### Phase 4 — 受け入れテスト

- [ ] #8 PC / スマートフォン / キーボードで確認する

完了条件:
- 横スクロールと矢印操作が機能する
- 画面幅が狭くても文章・ボタンが欠けない
- Enter / Space で操作できる
- 最終パネルに誤った「次へ」表示がない
- 外部リンクが正しい場所へ移動する
- 動きを減らす設定が尊重される

### Phase 5 — 八コマ化の判断

- [ ] #7 八コマ原稿をどの単位で実装するか決める

判断材料:
- 4コマのまま要点を絞るか、各アクションを8コマにするか
- 8コマの場合も横一列を維持するか、別の見せ方にするか
- スマートフォンで長すぎないか
- 1コマ1アクションの原則を守れるか

**現時点の推奨:** まず4コマ版の改善を完了し、利用者テストで説明不足が残る箇所だけ八コマ化する。

## 進行ルール

- 既存Issue #1〜#6を重複作成しない。
- Issue単位で変更し、完了条件を満たしたらクローズする。
- 画面変更後は両ビューを必ず確認する。
- 年齢・権限に関する文言は、実装前に公式ポリシーの最新情報と照合する。
